# CoDoc: главная страница, шаблоны и аналитика

Главная описывает подтверждённые возможности `ticket-editor` и `ticket-pdf`: визуальный макет, схемы полей, наборы данных, импорт JSON, генерация PDF/PDF-A/SVG и ZIP. Неподтверждённые тарифы, отзывы, сроки внедрения и интеграции удалены. Общие тексты входа и регистрации вынесены в `AuthProductAside`.

## Путь пользователя

Главная → регистрация/вход с сохранением намерения → `/app/templates/new` → название и необязательная схема → сохранённый серверный шаблон → редактор → данные → генерация.

Кнопка в списке шаблонов, стартовая карточка и навигация ведут к созданию настоящего шаблона, без промежуточного документа. Шаблоны доступны в боковом меню. После сохранения редактор предлагает следующие шаги. Схема передаётся между страницами через `schemaId`. Локальный режим с главной по-прежнему ведёт в локальный редактор.

## Яндекс Метрика

События создания схем, моделей, шаблонов и генерации документов описаны в [METRICS.md](METRICS.md): идентификаторы целей, параметры и ограничения подсчёта.

Подключён счётчик **114057241** для `codoc.site`: номер указан в `.env.production` и как значение по умолчанию для Docker-сборки. Его можно переопределить переменной окружения сборки. Поступление статистики в личный кабинет нужно проверить после публикации.

1. Создайте счётчик для `https://codoc.site` в Яндекс Метрике.
2. Укажите `VITE_YANDEX_METRIKA_ID=ВАШ_НОМЕР` в окружении **сборки** или в `.env.production` и пересоберите приложение.
3. Для Docker из корня `C:/sandpr` передайте `docker build --build-arg VITE_YANDEX_METRIKA_ID=ВАШ_НОМЕР -f ticket-infra/Dockerfile .`.
4. Если используете GitHub Actions, передайте эту переменную в шаг `Build project`.
5. Создайте JavaScript-цели `start_template`, `template_created`, `template_saved`. Для первой передаётся место нажатия `placement`.
6. После выкладки проверьте загрузку `https://mc.yandex.ru/metrika/tag.js` и поступление просмотров/целей в интерфейсе Метрики.

Просмотры SPA отправляются через `hit`, автоматический первый просмотр отключён через `defer: true`. Параметры URL и идентификаторы документов в `hit` не передаются. Вебвизор, карты кликов и автоматическое отслеживание ссылок выключены. Изменён CSP в `ticket-infra/nginx.conf`, иначе он блокировал бы Метрику. Блокировщик рекламы может мешать сбору статистики.

Документация Яндекса: [SPA](https://yandex.ru/support/metrica/ru/code/counter-spa-setup), [CSP](https://yandex.ru/support/metrica/ru/code/install-counter-csp).

## SEO и публикация

- Русский язык страницы, title, description, canonical, Open Graph, Twitter Card, JSON-LD WebApplication.
- `npm run build` дополнительно создаёт HTML главной из того же React-компонента. Поисковик получает содержимое без выполнения JavaScript; сервер SSR не нужен.
- `public/robots.txt` закрывает рабочую область, API и авторизацию. `public/sitemap.xml` содержит публичную главную.
- После публикации проверьте `/robots.txt`, `/sitemap.xml`, изображение Open Graph и текст главной в исходном HTML.
- В [Яндекс Вебмастере](https://webmaster.yandex.ru/) подтвердите права на `https://codoc.site` предложенным сервисом способом и добавьте `https://codoc.site/sitemap.xml`. Код подтверждения должен принадлежать вашему аккаунту — выдуманного кода в проекте нет.
- Аналогично можно добавить sitemap в Google Search Console. Настройки помогают обнаружить и понять страницу, но не гарантируют позиции и сроки индексации.

## Иллюстрации

Созданы встроенным инструментом imagegen, проверены визуально и сохранены в WebP:

- `public/images/document-studio.webp` — 1536×1024, главный экран.
- `public/images/template-series.webp` — 1200×800, иллюстрация пакетной генерации.

Точные промпты: `docs/image-prompts.md`. Карточки примеров выполнены в HTML/CSS и прямо обозначены примерами оформления, а не готовой библиотекой шаблонов.

## Проверка

`npm run check`, `npm run lint:strict`, `npm test`, `npm run build`; браузерные проверки: `npm run e2e`. В Windows с установленным Edge можно задать `PLAYWRIGHT_CHANNEL=msedge`. Тесты API используют заглушки; реальную серверную генерацию и отправку Метрики нужно проверить после публикации с рабочим backend и номером счётчика.
