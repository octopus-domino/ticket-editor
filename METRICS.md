# События продукта в Яндекс Метрике

Счётчик: **114057241**. События включены в production-сборке. После публикации в Метрике откройте **Цели → Добавить цель → JavaScript-событие** и создайте следующие идентификаторы. Название цели в интерфейсе можно написать по-русски.

| Идентификатор | Когда отправляется | Параметры |
| --- | --- | --- |
| `schema_created` | Сервер создал схему — в том числе из панели рядом с холстом и из документа | `field_count` |
| `model_created` | Сервер создал модель или подтвердил импорт | `source`: `manual` / `import`; `model_count` |
| `template_created` | Сервер создал шаблон через новый шаблон или сохранение документа в шаблоны | `slide_count`, `has_schema` |
| `generation_started` | Начата попытка генерации или прямого экспорта | `source`, `mode`, `format`, `requested_count`, `resumed` |
| `generation_completed` | Результат получен приложением либо завершён экспорт из редактора | те же, плюс `document_count`, `failed_count`, `outcome`, `duration_ms` |
| `generation_failed` | Ошибка запроса, фоновой генерации, опроса или получения результата | основные, плюс `stage`, `duration_ms` |
| `generation_cancelled` | Подтверждена отмена фоновой задачи | основные параметры генерации |

## Как читать показатели

- `source=generation` — документы из шаблона и моделей, с отдельной страницы генерации и панели рядом с холстом. `source=editor_export` — прямой экспорт макета.
- `mode=sync/async/local`: обычная генерация, фоновая задача или локальный SVG. `format=pdf/pdfa/svg`.
- `requested_count` — запрошенное число документов. `document_count` — число успешных документов, а не страниц PDF. Многостраничный PDF при прямом экспорте считается одним документом.
- `outcome=success/partial/failed` отделяет полный результат от частичных ошибок.
- `resumed=true` — восстановление задачи после перезагрузки. Второго `generation_started` нет; `duration_ms` считается с восстановления наблюдения. Формат не содержится в статусе API и обозначается `unknown`. Пока статус не получен, `requested_count` тоже `unknown`.
- При bulk-импорте моделей отправляется одно событие с подтверждённым `model_count`. Число достижений цели — число операций, а не число импортированных моделей/документов.

Для просмотра параметров используйте отчёт **«Параметры событий»**. Воронку можно строить от создания схемы/шаблона через создание модели к `generation_completed`; порядок выбирайте под исследуемый путь, так как можно начинать и с макета, и с данных.

## Защита от лишних событий

Открытие страницы, редактирование, переименование и автосохранение существующей сущности не считаются созданием. Неуспешное создание и ответы после сброса сессии тоже не считаются. Обновления прогресса задачи и «Скачать снова» не создают новые события генерации. Терминальное событие отправляется один раз в рамках текущей операции.

Ранее добавленное `template_saved` остаётся отдельным событием сохранения. Для количества новых шаблонов используйте `template_created`: оно перенесено из UI в `TemplateStore`, чтобы охватить все пути создания без двойного события.

## Если просмотры есть, а цели пустые

1. В счётчике **114057241** проверьте тип цели **JavaScript-событие** и идентификатор: например, строго `schema_created`, а не отображаемое название «Создана схема». Регистр и написание должны совпадать с таблицей.
2. Откройте `https://codoc.site/?codoc_metrics_debug=1`, включите Console в инструментах браузера и выполните **новое** создание. Флаг диагностики сохраняется при переходах SPA до перезагрузки. Открытие/редактирование ранее созданной схемы не отправляет `schema_created`.
3. В консоли должны быть `[CoDoc metrics] goal_called` и имя цели. `goal_callback` означает callback библиотеки Метрики после вызова отправки, но не гарантирует появление строки в отчёте.
4. Нет `goal_called` — проверьте опубликованную сборку и выполненное действие. Есть `disabled` — сборка не production или в неё не попал номер счётчика. Есть `script_blocked_or_unavailable` — проверьте CSP, сеть и блокировщик.
5. Есть вызов и callback, но отчёт пустой — проверьте идентификатор/тип цели в нужном счётчике, период отчёта и фильтры, в частности «Не учитывать мои визиты». Данные в отчётах могут появляться не сразу. У приложения нет доступа к настройкам вашего счётчика.

Также можно использовать [официальный отладчик](https://yandex.ru/support/metrica/ru/general/check-goal): `https://codoc.site/?_ym_debug=2`. Собственная диагностика приложения включается и этим параметром. Диагностика выводит только безопасные параметры существующих событий и не сохраняется локально.

## Приватность и ограничения

Передаются только фиксированные категории, формат, счётчики и время. Имена пользователей, названия полей/схем/шаблонов/файлов, ID сущностей, значения моделей, содержимое документов и сообщения ошибок не включаются. Сбой Метрики не мешает основным операциям.

Это клиентская аналитика: блокировщик, закрытая вкладка или отсутствие сети могут помешать отправке. Завершение фоновой задачи, которую пользователь больше не открывал, на клиенте не наблюдается. Управлять целями через публичный номер счётчика нельзя: цели в вашем аккаунте автоматически не создавались.

Документация: [JavaScript-цели](https://yandex.ru/support/metrica/ru/general/goal-js-event), [параметры событий](https://www.yandex.com/support/metrica/ru/reports/event-params).
