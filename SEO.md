# Поисковое продвижение CoDoc

## Что подготовлено в коде

| URL | Задача посетителя |
| --- | --- |
| `/` | Понять возможности конструктора шаблонов |
| `/stamps/` | Создать штамп или макет печати и добавить его в документ |
| `/certificates/` | Создать сертификат или серию персональных сертификатов в PDF |
| `/tickets/` | Сделать билет, бейдж или пропуск с QR-кодом |
| `/pdf-generator/` | Получить PDF из шаблона и своих данных |

Страницы содержат самостоятельные инструкции, примеры сценариев, ограничения и ответы на вопросы. Ссылки доступны из главной и между разделами. Для каждой страницы заданы отдельные title, description, canonical, Open Graph и структурированные данные. Названия и тексты описывают реально существующие функции: готовая библиотека шаблонов, продажа/проверка билетов и реестр сертификатов не обещаются.

`npm run build` создаёт отдельный HTML каждой страницы и sitemap. Контент доступен без JavaScript, отдельный SSR-сервер не нужен. `npm run check:seo` проверяет полученные HTML: уникальные метаданные, H1, canonical, JSON-LD, sitemap и noindex для 404.

Тяжёлый код холста, редактора, email-превью и библиотек элементов загружается при открытии рабочей области. На публичных страницах он не предзагружается. Nginx возвращает настоящую 404 для неизвестных публичных адресов; технические маршруты приложения остаются SPA. Рабочая область и авторизация не включены в sitemap и закрыты от индексации.

## Действия после публикации

1. Подтвердите `https://codoc.site` в [Яндекс Вебмастере](https://webmaster.yandex.ru/) и [Google Search Console](https://search.google.com/search-console). У приложения нет доступа к вашим кабинетам, поэтому эти действия автоматически не выполнены.
2. Если выбран способ с метатегом, возьмите только значение `content` выданного сервисом тега и задайте `VITE_YANDEX_VERIFICATION` / `VITE_GOOGLE_SITE_VERIFICATION` перед сборкой. При Docker-сборке передайте соответствующие `--build-arg`. Это публичные коды подтверждения владения, а не API-токены. После изменения нужна новая сборка и выкладка.
3. В обоих сервисах добавьте `https://codoc.site/sitemap.xml`.
4. В Яндекс Вебмастере запросите переобход четырёх URL из таблицы. В Google используйте проверку URL и запрос индексации для этих страниц.
5. Проверьте доступность страниц с кодом 200, отсутствие `noindex` у публичных страниц и отсутствие блокировки роботов CDN/защитой хостинга. У неизвестного URL должен быть код 404.
6. Выберите единый основной адрес: в коде canonical и sitemap используют `https://codoc.site`. На внешнем HTTPS-прокси настройте согласованный 301 с `www`/HTTP на основной домен; этот прокси и сертификаты данным репозиторием не управляются.

## Как оценивать результат

- Вебмастер/Search Console: появились ли страницы в индексе, какие поисковые запросы дают показы, клики и какие позиции у отдельных страниц.
- Метрика: визиты из поисковых систем и переходы от публичной страницы к созданию шаблона (`start_template`), успешному созданию сущностей и генерации.
- Сравнивайте одинаковые периоды. Сначала важны доступность и индексация, затем показы, клики и конверсии, а не только позиция по одному общему запросу.

Техническая подготовка не гарантирует индексацию или конкретные позиции. Для роста нужны полезность продукта, реальные публикации и упоминания у целевой аудитории. Можно показывать реальные примеры использования в сообществах организаторов мероприятий и преподавателей, публиковать собственные инструкции и разбирать вопросы пользователей. Фиктивные отзывы, покупка спам-ссылок и накрутка посещений не добавлялись.

## Проверка сервера

```sh
curl -I https://codoc.site/
curl -I https://codoc.site/stamps/
curl -I https://codoc.site/certificates/
curl -I https://codoc.site/tickets/
curl -I https://codoc.site/pdf-generator/
curl -I https://codoc.site/page-that-does-not-exist
```

Полная проверка: собрать frontend, выполнить `npm run check:seo`, затем проверить опубликованные страницы через инструменты обоих поисковиков. Docker/Nginx runtime в этой рабочей среде недоступен, серверные статусы нужно проверить после выкладки.

Источники: [Google о JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Google о canonical и sitemap](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [Яндекс о Sitemap](https://www.yandex.ru/support/webmaster/ru/indexing-options/sitemap), [Яндекс о переобходе](https://www.yandex.ru/support/webmaster/ru/robot-workings/site-reindex).
